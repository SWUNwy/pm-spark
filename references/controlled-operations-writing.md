# 操作文档与故障排查的受控写作

适用：操作手册、安装与部署步骤、故障排查、运维 Runbook、安全警告、多步骤 API 调用流程。目标是把执行风险降到最低：读者按文档操作时，条件清楚、动作明确、结果可判断、失败有退路。

本规范吸收受控语言写作中可迁移到中文的方法，但**不宣称符合任何认证标准**；不同语言的受控词典、词性与句长规则不能直接移植。

## 适用范围分级

- **完整应用**：操作手册、安装部署步骤、故障排查、运维 Runbook、安全警告、多步骤 API 流程。
- **选择性应用**：API 概念说明、FAQ、更新日志、产品能力说明——只应用术语一致、指代明确与事实保真，不强制把句子改成操作步骤。
- **不机械应用**：品牌与落地页文案、叙事文章、法律原文与正式引用、需要保留作者风格的内容、极短按钮与导航标签。

## 六条原则

1. **保留事实**：不新增来源没有的数字、日期、时限、能力、条件或结论；不删除警告、限制、例外、单位、默认值与失败处理；不改变「可能」「建议」「计划」「通常」表达的确定程度。
2. **一概念一术语**：关键对象、状态、动作确定首选术语；不轮换同义词；首次缩写给全称；项目名词来自目标项目术语表。
3. **一步骤一动作**：步骤以明确动作开始；写清动作对象，不只写「处理」「操作」「执行」；必须按顺序执行的动作拆成编号步骤；不可分割的操作保留在同一步；不为拆句牺牲必要条件、否定与因果关系。
4. **条件与风险先于动作**：执行前必须知道的条件放在动作之前；警告放在可能造成风险的步骤之前；条件多时单独列前置条件；不把关键限制放在步骤末尾括号里。
5. **明确执行者、对象与结果**：可能出现责任或指代歧义时写出执行者；区分系统自动行为与人工操作；必要时说明预期结果；不使用无法定位对象的「该」「其」「此」「上述」「相关」。
6. **保持逻辑顺序**：按实际执行顺序描述；故障排查先给低风险、可逆、证据价值高的检查；把原因、现象、操作、结果分开，不混在长句中；否定范围必须明确。

## 操作步骤模板

在适用时按以下结构组织：

1. 前置条件
2. 风险或限制
3. 编号操作步骤
4. 每一步的预期结果
5. 失败时的停止条件与恢复方式

不补造原文没有的预期结果或恢复步骤；资料缺失时标记「待确认」。

## 故障排查模板

1. 说明可观察到的现象。
2. 说明需要收集的日志、状态或错误码。
3. 按证据与风险安排检查顺序。
4. 对每项检查写明判断条件。
5. 只有证据支持时才给出原因。
6. 写明恢复操作、验证方式与停止条件。

不要把「可能原因」改写成「确定原因」。

## 样例（带检查点）

### 操作手册

改写前：`在安装代理程序之前需要确认服务器能够访问更新地址，然后运行安装命令。`
改写后：
1. `确认服务器能够访问更新地址。`
2. `运行安装命令。`

检查点：条件位于动作之前；没有增加网络地址或命令。

改写前：`选择保存以后系统会写入配置并重新加载服务。`
改写后：`选择「保存」。系统随后写入配置并重新加载服务。`

检查点：区分人工动作与系统行为，不把系统行为误写成人工步骤。

### API 调用

改写前：`调用接口前应配置访问令牌，否则请求会返回认证错误。`
改写后：`调用接口前，配置访问令牌。未配置访问令牌时，请求返回认证错误。`

检查点：前置条件与失败结果分开；未补充状态码。

改写前：`请求失败时最多重试 3 次，每次间隔 5 秒。`
改写后：`请求失败时，最多重试 3 次。每次重试间隔 5 秒。`

检查点：原有次数与间隔保持不变。

### 故障排查

改写前：`页面无法打开时可能是网络问题，可以先检查浏览器是否能够访问其他站点。`
改写后：`页面无法打开时，先检查浏览器能否访问其他站点。网络异常是可能原因之一。`

检查点：没有把可能原因写成确定原因。

改写前：`排查期间不要删除日志文件，因为后续分析还需要这些文件。`
改写后：`排查期间，不要删除日志文件。后续分析仍然需要这些文件。`

检查点：保留禁止动作与原因。

### 产品介绍（边界示例）

改写前：`平台提供任务创建、状态查询和结果下载能力。`
改写后：`平台提供任务创建、状态查询和结果下载能力。`

检查点：原文已清晰，不为追求变化而改写。

改写前：`系统通常会在任务完成后发送通知。`
改写后：`系统通常在任务完成后发送通知。`

检查点：保留「通常」表达的不确定程度。

## 自动检查边界

可稳定自动检查：确定错字、明确术语大小写、机器可读内容是否被误处理、项目词表中的确定映射。

只应提示人工判断：句子是否含过多动作、条件是否应提前、主语是否需要显式写出、代词是否有歧义、被动表达是否影响理解、文本是否过度简化、改写是否改变事实或确定程度。

不要把句长、被动句、代词或语境词设为无条件失败规则。自动检查只能提供提示，不能证明文本语义正确，也不能代替作者判断。
