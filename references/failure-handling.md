# 结构化失败处理（Structured Failure Handling）

使用第一个匹配的失败模式。记录症状、诊断、改变的策略、状态转换与停止条件。

| 失败模式 | 检测信号 | 必需动作 | 状态/停止行为 |
|---|---|---|---|
| 低信息循环 | 三个回答都没有增加决策相关信息 | 停止宽泛提问；提供有界选项或降级输出 | 保持 scoped/synthesizing；只等待一个决定性输入 |
| 分支过载 | 活跃分支 >3 或反复切换主题 | 保留分支图；选一条主线并检查点其余分支 | 分支可独立交付时要求 G-Decompose |
| 路由模糊 | 两个轨道暗示不同交付物 | 按请求结果路由；声明主导轨道与子步骤 | 仅当交付物实质冲突时等待用户 |
| 证据不可访问 | 必要私有/本地/外部来源读不到 | 记录尝试过的来源与失败；只有诚实时才用条件分析 | 缺失证据起决定性作用时，阻止确定性结论 |
| 证据矛盾 | 权威来源支持互斥声明 | 按权威/时效/范围排序；找解决责任人或条件分支 | 无解决途径时 stop/block |
| 易变事实风险 | 建议依赖未验证的当前事实 | 通过授权来源验证，或把分支标为条件 | 高风险承诺不能通过 G-Human |
| 门禁两次被阻 | 实质改变修复后同一门禁仍失败 | 重评路由、深度、范围或证据负担 | 消耗修复预算；到上限停止 |
| 范围漂移 | 新工作不再符合目标/非目标 | 创建分支/新 run，或显式修订契约 | 不要静默扩大当前 run |
| Constitution 冲突/漂移 | 约束冲突或哈希变化 | 停止推进；重新评估 Constitution 与过期门禁/工件 | 保持 intake/awaiting_user/blocked 直到解决 |
| 上下文中断 | 对话被压缩或工作中断 | 从 state + 最近已验证检查点 + 证据台账恢复 | 绝不从未经验证的生成文字恢复 |

## 降级输出

- Preliminary Judgment（初步判断）
- Evidence Gap List（证据缺口清单）
- Open Questions Brief（开放问题简报）
- Decomposition Map（拆解图）
- Contradiction Matrix（矛盾矩阵）
- Stop/Block Summary（停止/阻塞摘要）
