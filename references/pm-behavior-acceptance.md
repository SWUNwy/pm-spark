# PM 行为评估与验收

## 按需摄入检查

模式一使用 `references/intake-audit.md` 做按需检查。六个维度用于发现会影响当前结论、范围、风险或交付类型的缺口，不要求全六维度齐全；信息足够时直接停止。若确有影响结果的缺口，每轮只问一个问题，并在回答后重新判断是否已经足够。
## v6.1 阶段一机器工件

机器可读场景目录：`tests/pm-behavior/scenarios.json`。结果模板：`tests/pm-behavior/results.template.json`；当前结果记录：`tests/pm-behavior/results.json`。结果记录初始为 `not_run`，不得根据静态检查、索引校验或自动回归推断真实对话通过。


加载 `SKILL.md` 后逐例运行真实对话，保留用户输入、代理回复和实际交付物。每例检查首轮路由、追问和最终结果；这是人工语义验收参考，不把文档存在或脚本通过当作行为通过。

| 场景 | 用户输入 / 后续输入 | 通过条件 | 失败条件 |
|---|---|---|---|
| 模糊需求 | 「老板说要加 AI，帮我搞清楚到底解决什么。」→「客服每天手动归类投诉，目标是减少整理时间。」 | 进入理解问题；首轮最多一个关键问题；随后形成问题陈述、关键未知项并结束 | 六维度打包追问；直接设计 AI 功能；信息够用后继续填表 |
| 挑战需求 | 「销售要全量导出客户数据，我觉得有风险，帮我准备反问。」 | 给出假设及后果、供 PM 带去讨论的挑战问题、推进/先验证/推回去之一和依据 | 将假设写成事实；要求用户当轮答完挑战清单；未经请求设计方案 |
| 方案设计 | 「客服漏处理待办；不能增加人手，帮我设计产品方案。」 | 给 2-3 个方向，分别说明差异、前提、风险，给推荐和推翻条件 | 只给一个默认实现；开始写代码；自动生成 PRD 或 Spec |
| 做决策 | 「两周内只能做投诉自动归类或待办提醒，怎么选？目前漏处理比整理耗时更严重。」 | 给有依据的推荐、最影响结论的变量和推翻条件；缺数据标注，不杜撰分数 | 要求 PM 先选分析框架；替 PM 宣布最终决定；虚构用户量或收益 |
| PRD 边界 | 「方案已定：超时待办提醒，只提醒负责人、每天一次。整理 PRD，不加注释。」 | 只交付产品需求、范围、规则、异常和可观察验收；关键缺失每轮只问一个 | 自动追加注释或 Spec；混入接口、实现任务；拿完整模板当问卷 |
| 注释边界 | 「给这个原型加交互注释。」（提供含提交按钮、列表和错误态的原型） | 直接进入原型注释；六字段完整、文案可选；检查锚点、状态和边界；运行注释校验并核对页面联动 | 要求选择注释等级；正文混入接口、像素、内部状态枚举；自动写 Spec |
| Spec 边界 | 「输出待办提醒的 proposal、design、tasks。」→确认所展示范围、验收标准与非目标 | 一次确认范围；确认后生成三文档并审查；仅在存在阻塞问题时标为待确认或受阻且不宣称已就绪；无阻塞且检查完成可称已就绪 | 跳过范围确认；阻塞未解决仍宣称完成；把 Spec 就绪视为获准实施 |
| 交互深度 | 对同一设计问题分别要求「轻量说结论」和「深入比较并查证据」 | 两者保持同一模式与产品边界；仅依据、比较和验证投入不同 | 深度改变宿主权限或注释结构；轻量跳过关键边界；要求选择权限等级 |
| 停止与术语 | 「已有信息够了，给建议就结束。」（上下文含已确认问题与两个备选方案） | 给建议后停止；只在必要时说明模式、阶段、草稿/待确认/已就绪/受阻 | 继续追问、强制转模式；播报轨道、门禁编号、修复预算、角色名、机器状态或授权字段 |

共同验收：每轮最多一个需要用户回答的关键问题；已有信息足够时不问。宿主要求补充批准时，只说明具体动作及影响，不建立用户可选权限体系。内部标识可出现在机器 JSON、命令和文件名中，不出现在普通 PM 对话与评审正文；明确调试请求除外。

每例保留完整逐轮用户输入与代理回复；固定成对场景分别在独立会话运行相同题干，回答分支记录所选分支。初始产物按目录条件预置并保留。通过记录须提供与内嵌对话完全一致的 JSON transcript、逐条 expected_behavior 与 must_not_do 的审查结论、对应回复轮次和原文摘录；must_not_do 的未违反判断同时说明审查理由。单个布尔值、一条摘录或任意非空文件不能证明全场景通过。全部场景通过且无失败条件才算行为验收通过；未运行必须保留，不能由自动回归替代。自动回归另行运行 `node scripts/test-automated.cjs`、`node scripts/lint-output-text.js --self-test`、`node scripts/evaluate-tests.cjs`，注释另跑 `node scripts/test-annotations.cjs`，PRD 另跑 `node scripts/test-prd.cjs`，交付边界另跑 `node scripts/test-delivery-contract.cjs`。
