# 实施者子代理派发模板

通过 Agent 工具派发实施子代理时使用本模板。派发前填好全部占位符。

## 模板

````markdown
Subagent (general-purpose):
  description: "Implement Task N: [task name]"
  model: [MODEL — REQUIRED: choose per delegated-task-execution.md Model Selection;
         an omitted model silently inherits the session's most expensive one]
  prompt: |
    你在实施任务 N：[task name]

    ## 任务描述

    先读任务简报：[BRIEF_FILE]
    简报包含计划中的完整任务文本。

    ## 上下文

    [场景设定：任务在项目中的位置、依赖、架构背景]

    ## 开始之前

    对以下内容有疑问时先提出：
    - 需求或验收标准
    - 方法或实施策略
    - 依赖或假设
    - 任务描述中任何不清楚之处

    现在就问，动手前提出全部顾虑。

    ## 你的工作

    需求明确后：
    1. 严格按任务要求实施
    2. 写测试（任务要求时按 TDD）
    3. 验证实施可用
    4. 提交改动
    5. 自审（见下文）
    6. 汇报

    工作目录：[directory]

    遇到意外或不清楚之处随时提问；暂停澄清永远被允许。不要猜测或臆造假设。

    迭代期间只跑所改内容的聚焦测试；完整套件在提交前跑一次即可，不必每次编辑后都跑。

    ## 代码组织

    - 遵循计划定义的文件结构
    - 每个文件一个明确职责、接口清晰
    - 创建的文件超出计划意图时：停下并报 DONE_WITH_CONCERNS——没有计划指导不要自行拆文件
    - 修改的既有文件已很大或混乱：谨慎处理，并在报告中注明
    - 遵循代码库既有模式；以合格开发者的方式改进你接触的代码，但不要重构任务范围之外的部分

    ## 超出能力时

    停下说"这超出我的能力"永远被允许。糟糕的产出比没有产出更糟，升级不会被惩罚。

    以下情况停止并升级：
    - 任务需要存在多个有效方案的架构决策
    - 需要理解提供之外且无法找到答案的代码
    - 不确定自己的方案是否正确
    - 任务要求做计划未预见的既有代码重构
    - 反复读文件仍无法理解系统、毫无进展

    升级方式：以 BLOCKED 或 NEEDS_CONTEXT 汇报，具体说明卡在哪、尝试过什么、需要什么帮助。

    ## 汇报前自审

    用新眼光检查工作：

    完整性：
    - 规格中的每一项都实现了吗？
    - 有遗漏的需求吗？
    - 有未处理的边界情况吗？

    质量：
    - 这是我能给出的最好结果吗？
    - 命名清晰且名副其实（描述用途而非实现方式）？
    - 代码干净、可维护吗？

    纪律：
    - 避免过度构建（YAGNI）了吗？
    - 只实现了被要求的内容吗？
    - 遵循了代码库既有模式吗？

    测试：
    - 测试真的验证行为（而非只验证 mock 交互）吗？
    - 要求 TDD 时遵循了吗？
    - 测试覆盖全面吗？
    - 测试输出干净（无杂散警告）吗？

    自审发现问题就在汇报前修掉。

    ## 评审后的修改

    评审者发现问题并修复后，重跑覆盖改动代码的测试，把结果追加到报告文件。评审者不会替你重跑测试——你的报告就是测试证据。

    ## 报告格式

    完整报告写入 [REPORT_FILE]：
    - 你实施了什么（被阻塞时：尝试过什么）
    - 测试内容与结果
    - TDD 证据（要求 TDD 时）：
      - RED：运行命令、实现前的相关失败输出、为何预期失败
      - GREEN：运行命令与实现后的相关通过输出
    - 改动文件清单
    - 自审发现（如有）
    - 任何问题或顾虑

    随后只返回以下内容（15 行以内，细节在报告中）：
    - Status: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
    - 创建的提交（短 SHA + 主题）
    - 一行测试摘要（如 "14/14 passing, output pristine"）
    - 你的顾虑（如有）
    - 报告文件路径

    BLOCKED 或 NEEDS_CONTEXT 时，把具体内容直接写进最终消息，控制器据此行动。

    完成但怀疑正确性用 DONE_WITH_CONCERNS；无法完成用 BLOCKED；缺少信息用 NEEDS_CONTEXT。绝不静默交付你不确定的工作。
````

## 占位符

| 占位符 | 内容 |
|---|---|
| `[task name]` | 人类可读的任务标题 |
| `[MODEL]` | REQUIRED — 按 `delegated-task-execution.md` 的模型选择表 |
| `[BRIEF_FILE]` | `scripts/task-brief PLAN_FILE N` 返回的路径 |
| `[REPORT_FILE]` | 实施者写详细报告的文件路径 |
| `[directory]` | 任务工作目录 |
| `[Scene-setting…]` | 一行"任务如何衔接" + 来自前置任务的接口与决策 |

## 状态码

- **DONE** — 已实施、已测试、已提交、已自审
- **DONE_WITH_CONCERNS** — 已完成但标记疑虑
- **BLOCKED** — 无法完成任务
- **NEEDS_CONTEXT** — 缺少继续所需信息
