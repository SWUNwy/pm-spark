# Test Cases — 从注释自动生成测试用例

> 基于 ANNOTATIONS 数据的 state 定义，自动生成标准测试用例。
> 每个状态对应一个测试用例，覆盖正向、异常、边界场景。

---

## 1. 测试用例结构

### 1.1 标准测试用例模板

```markdown
### TC-{组件ID}-{序号}: {测试用例标题}
- **前置条件:** {从 trigger 和 context 提取}
- **操作步骤:**
  1. {步骤 1}
  2. {步骤 2}
  3. {步骤 3}
- **预期结果:** {从 state 描述提取}
- **验证点:** {关键验证项}
- **测试数据:** {从 api 和 fields 提取}
```

### 1.2 字段映射来源

| 测试用例字段 | ANNOTATIONS 来源 | 提取规则 |
|------------|-----------------|---------|
| 组件 ID | 组件 key（如 C01） | 直接使用 |
| 测试用例标题 | state 键名 + 行为描述 | {状态} 场景：{行为概述} |
| 前置条件 | trigger + context | 触发条件 + 权限/上下文 |
| 操作步骤 | trigger + behavior | 按触发条件生成步骤 |
| 预期结果 | state 值 | 该状态下的组件表现 |
| 验证点 | state + 类型模板 | 类型特定的关键验证 |
| 测试数据 | api + fields + data | 接口参数和字段定义 |

## 3. 边界值测试

从 ANNOTATIONS 的 fields/columns/data 定义中提取边界值测试用例：

| 测试类型 | 提取来源 | 测试用例 |
|---------|---------|---------|
| 字段长度 | fields 定义中的长度约束 | 超长输入 → 截断/报错 |
| 数值范围 | data 定义中的 min/max | 超界值 → 报错/舍入 |
| 枚举值 | fields 定义中的枚举列表 | 非法值 → 报错 |
| 空值 | fields 定义 | 空字符串 → 校验不通过 |
| 特殊字符 | fields 定义 | 特殊字符 → 转义/过滤 |

## 4. 异常场景测试

从 ANNOTATIONS 的 api 和 state 定义中提取异常场景：

| 异常类型 | 提取来源 | 测试用例 |
|---------|---------|---------|
| 网络超时 | api.error | 超时 → 友好提示 + 重试 |
| 服务不可用 | api.error | 500 → 错误展示 |
| 业务冲突 | api.error | 409 → 具体错误提示 |
| 权限不足 | context (Block C) | 无权限 → 按钮隐藏/禁用 |
| 重复提交 | state.submitting | 防重复提交验证 |

## 5. 自动生成格式

### 5.1 Markdown 格式

```markdown
# Test Cases — {组件名}

## 正向用例

### TC-{ID}-001: {场景描述}
- **前置条件**: {条件}
- **操作步骤**: {步骤}
- **预期结果**: {结果}
```

```json
{
  "componentId": "C01",
  "testCases": [
    {

      "steps": ["进入页面"],
      "expected": "指标数据正确展示",
      "type": "positive"
    }
  ]
}
```
