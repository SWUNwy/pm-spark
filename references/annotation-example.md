# 注释约束示例（PM 评审视图）

本文件定义 PM 注释的**标准形态**，用于 8F 输出生成的对照基准。PM 注释只包含产品层内容，不含研发实现细节。

---

#### PM 注释示例：@登录表单（T6 表单填写）

```
summary: 邮箱+密码登录，校验后提交，失败保留输入。

annotation:
  feature: 用户通过邮箱和密码登录账户，校验通过后跳转首页。

  logic:
    · 邮箱输入框失焦 → 校验格式，错误时红框 + 错误文案
    · 点击「登录」→ 校验全部字段 → 提交
    · 登录成功 → 跳转首页
    · 登录失败 → 顶部 Toast 提示错误原因，表单保留已填内容

  states:
    · 空表单（初始态）
    · 校验错误（字段红框 + 文案）
    · 提交中（按钮 loading，disabled）
    · 成功（跳转，表单消失）
    · 失败（Toast 错误提示，表单可重试）
    · hover：按钮颜色加深
    · disabled：按钮置灰，不可点击

  boundary:
    · 邮箱：必填，格式校验（含@），≤50字符
    · 密码：必填，6-32位
    · 连续失败5次：显示验证码（边界条件）
    · 账号不存在或密码错误：统一提示「邮箱或密码不正确」，不区分具体原因

  copy:
    · 按钮：「登录」/ 提交中：「登录中…」
    · 邮箱错误：「请输入有效邮箱」
    · 密码不足：「密码至少 6 位」
    · 登录失败 Toast：「邮箱或密码不正确，请重试」
```

---

## 必含清单（约束）

1. `summary`：1-2句摘要，供目录视图快速扫读，**必须存在**
2. `feature`：1-3句，说明组件的产品定位，无技术描述
3. `logic`：步骤式，用户操作 → 界面响应，不含 API 调用或实现细节
4. `states`：列举用户可见状态 + 视觉设计状态（hover/disabled/loading），不含内部状态机枚举
5. `boundary`：产品边界和异常分支，不含技术约束（如"数据库索引"）
6. `copy`：关键文案；**无关键文案时省略此字段**

---

## 边界（禁止出现在 PM 注释中的内容）

| 禁止内容 | 示例 |
|---------|------|
| API 路径 | `/api/auth/login` |
| HTTP 状态码 | `200 / 401 / 400` |
| CSS 像素值 | `border-radius: 8px; height: 40px` |
| timing 参数 | `200ms fade; 100ms debounce` |
| 无障碍规范 | `aria-label; Tab 顺序` |
| i18n key | `btn.login; error.format` |
| 数据库/接口字段名 | `snake_case 字段名` |
| 内部状态机枚举 | `normal / fieldError / submitting / success / apiError` |
