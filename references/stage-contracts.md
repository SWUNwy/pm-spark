# 轨道阶段契约（Track Stage Contracts）

轨道契约定义每个认知轨道必须完成什么。生命周期状态定义**何时**发生工作；两者不要混淆。

## Explore

**目的：** 在不仓促承诺的前提下，揭示有用的方向、假设与决策变量。

**最小输入：** 问题种子、排除项、期望的进展形式。

**完成信号：**

- 2-3 个有意义的不同方向，或存在"更少"的显式理由。
- 假设与开放问题可见。
- 分支有组织；失控扩展已停止。
- 用户可选择：继续探索、分析某个方向、或停止。
- G-Explore 通过。

**下一阶段候选：** 比较/排序进入 Analyze；仅当范围与验收已成熟时进入 Specify；当探索本身就是交付物时，以 Direction Brief 完成。

## Analyze

**目的：** 产出站得住脚的需求、决策、方案或战略判断。

**最小输入：** 决策/问题陈述、标准/证据标准、范围、非目标。

**完成信号：**

- 主导 `analysis_type` 明确。
- 发现/选项映射到证据或标注推理。
- 存在清晰的倾向、置信度、备选方案与失效触发条件。
- Solution/Mixed 分析通过 G-Architecture。
- G2、self-review、G3 通过。

**下一阶段候选：** 正式交接进 Specify；选项集过早过窄时回 Explore；判断/报告就是交付物时完成。

## Specify

**目的：** 冻结可实施交接，但不授权实施。

**最小输入：** 选定方向、范围、非目标、验收标准、假设/依赖、工件清单、输出路径。

**完成信号：**

- G-Spec 通过。
- Standard/Verified 工作完成章节评审并通过 G-Section。
- 工件内部一致且经过评审。
- 验收标准可追溯到场景、任务与验证。
- 交接要求与项目 Constitution 覆盖项明确。
- G3 通过。

**下一阶段候选：** 下游宿主规划/执行工作流；仍有缺口时回 Analyze。绝不自动进入实施。

## 契约选择

```json
{
  "purpose": "...",
  "deliverable": "...",
  "completion_signals": ["..."],
  "next_stage_candidates": ["..."]
}
```

G1 证据必须显示：所选 Track 契约已为当前任务实例化。
