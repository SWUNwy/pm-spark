# 类型化注释模板

## 1. 当前交付契约

所有 PM 注释使用六字段：`summary` / `feature` / `logic` / `states` / `boundary` / `copy`。组件类型只决定需要说明哪些行为和状态；用户无需选择注释深度或标签。

| 字段 | 必填 | 内容 |
|---|---|---|
| summary | 是 | 1–2 句核心摘要，支持目录扫读 |
| feature | 是 | 组件用途、解决的问题与功能范围 |
| logic | 是 | 用户触发 → 界面响应 → 结果，含关闭、取消及联动行为 |
| states | 是 | 所有适用的用户可见状态及表现 |
| boundary | 是 | 可见/可操作条件、权限限制、输入边界与异常分支 |
| copy | 否 | 关键按钮、提示、空态、错误文案；无文案时省略 |

`type` 为组件元数据，必须为 T1–T11。普通 `ANNOTATIONS` 条目采用平铺六字段；评审模式的 `summary` 和 `type` 位于条目顶层，其余五字段放在 `annotation` 中。两种结构内容一致。

```json
{
  "create": {
    "type": "T6",
    "summary": "填写信息后创建成员。",
    "feature": "为管理员提供成员创建入口。",
    "logic": "点击创建打开表单；填写后提交，成功关闭并刷新列表；取消放弃本次填写。",
    "states": "初始可填写；填写错误时显示字段提示；提交中防止重复操作；成功刷新；失败保留内容并可重试。",
    "boundary": "仅管理员可操作；必填信息缺失时不可提交；关闭未保存内容时提示确认。",
    "copy": "创建成员；提交中；创建成功；请填写姓名。"
  }
}
```

默认输出遵循 `delivery-contract.json` 的 product 边界。API 路径、请求响应结构、内部状态机、CSS 参数、动效时长、ARIA 属性、国际化键仅在用户明确选择工程交接后写入独立 implementation 文档，不混入 PM 注释。

## 2. 组件类型分类

分类依据为交互模式，代理自动选择类型；仅在行为不明确时澄清。

| ID | 类型 | 交互模式 | 典型实例 |
|---|---|---|---|
| T1 | DisplayMetric | 只读指标展示 | 统计卡片 |
| T2 | DataList | 列表、分页、排序、选择 | 数据表格 |
| T3 | ActionButton | 单操作触发 | 添加按钮 |
| T4 | ActionMenu | 多选一操作 | 操作菜单 |
| T5 | ConfirmAction | 二次确认 | 删除确认 |
| T6 | FormFill | 填写、校验、提交 | 创建表单 |
| T7 | ItemSelect | 搜索、筛选、选择、确认 | 选择弹窗 |
| T8 | SearchSelect | 搜索式选择输入 | 自动补全 |
| T9 | Toast | 瞬态反馈 | 成功提示 |
| T10 | StatusPlaceholder | 空、加载、错误占位 | 空列表 |
| T11 | PageInfo | 辅助说明 | 帮助气泡 |

复合组件按最外层交互模式分类，有独立行为的子组件单独列举。弹窗是上下文，按实际行为选 T5/T6/T7。无法归类的高度交互组件在设计文档中明确行为后再选类型，不用标签替代描述。

## 3. PM 字段按类型填充

| 类型 | logic 需说明 | states 最低适用覆盖 | boundary 需说明 |
|---|---|---|---|
| T1 | 更新时机、指标口径、点击行为（如有） | 正常、加载、失败 | 统计范围、可见权限、零值策略 |
| T2 | 列内容、排序、筛选、分页、选择、行操作 | 正常、加载、空数据、失败 | 数据范围、跨页选择、无权限、无匹配 |
| T3 | 触发方式、操作结果 | 正常；有条件禁用时禁用；异步操作时处理中 | 可操作条件、重复触发 |
| T4 | 菜单项全列举、选择结果、收起方式 | 折叠、展开、不可用 | 各项可用条件、权限 |
| T5 | 触发来源、确认结果、取消不执行 | 待确认、提交中、失败 | 操作影响范围、取消、重复提交 |
| T6 | 字段、默认值、校验时机、提交结果、关闭行为 | 可填写、字段错误、提交中、成功、失败 | 必填、长度/范围/选项、排重、未保存退出 |
| T7 | 搜索、筛选、选择模式、确认、取消 | 正常、加载、空数据、无匹配、已选择、确认中、失败 | 可选范围、选择上限、不可选原因 |
| T8 | 搜索匹配范围、选中后显示与联动、收起 | 空闲、聚焦、搜索中、已选中、无结果、失败 | 无权限、清空、失效选项 |
| T9 | 何种结果触发、展示与消失 | 展示、隐藏 | 连续提示、错误恢复 |
| T10 | 每种占位内容、重试或补充操作 | 空数据、加载、失败 | 何时恢复正常、操作不可用 |
| T11 | 展开、说明内容、关闭 | 隐藏、展示 | 无内容、可见范围 |

状态内容必须描述用户看到什么、能做什么、如何恢复；不可只列举状态名称。适用状态全部覆盖，条件不适用时在 `boundary` 说明理由。类型要求不会因为组件简单而省略关键异常。

## 4. 内容与完整性规则

- 使用产品语言和完整陈述句；不写实现代码、模糊词或未替换占位文本。
- 枚举、菜单项、字段和异常分支完整列出；数值明确上下限。
- 同一术语、同一业务规则在组件间一致；引用使用 `→ design.md §章节` 或 `→ F001`。
- 表单字段规则写入 `logic` / `boundary`，关键提示写入 `copy`；指标口径写入 `feature` / `logic`。
- 字段级注释如独立交付，也使用六字段与适当组件类型，不引入另一套 PM schema。
- 父子组件共享规则在正文明确引用来源，子组件限制更严格时说明差异。

## 5. 组件枚举与同步

先列出全部交互组件、类型和锚点，确认无遗漏、无幽灵项，再逐组件填写六字段。Component Manifest 记录 ID、名称、类型、位置、字段完整性与待澄清项。

同一份结构化数据渲染 HTML 和设计文档。注释变更必须同步 `design.md`，需求引用变化时同步 `proposal.md` / `tasks.md`。HTML 中修正的行为、状态和边界必须反向同步后再交付。

## 6. 验证

```bash
node scripts/validate-annotations.js prototype-annotated.html
node scripts/validate-annotations.js annotations.json --json
bash scripts/check-annotations.sh annotated-delivery/
node scripts/test-annotations.cjs
```

校验器验证组件类型、五个必填 PM 字段、可选文案的字符串完整性、未知字段、未完成占位、评审场景结构、scopeMark 和 protoId 配对。类型状态覆盖及产品语义由作者和评审者依据 §3 核对；脚本不声称能自动判断自然语言是否覆盖全部业务场景。

## 7. 工程交接与旧数据迁移

工程交接使用独立 implementation 文档说明 API、字段结构、内部状态机、视觉与无障碍要求，按实际需求填写，不使用注释深度标签。

旧 `blocks` / `state` / `context` 及 `VIEW_DESCS` 仅可通过 `--legacy` 显式兼容读取。这是旧文件检查入口，不是当前输出模板；检查报告不会透传旧注释元数据。

`--migrate` 从旧注释读取可确定的摘要、行为和状态，写出相邻的 `<原文件>.pm.json`，原文件保持不变。旧等级字段只被忽略，永不写入迁移输出；无法推断的 PM 字段留空并使校验失败，必须补充产品信息后才能交付。迁移不会编造产品边界，也不会覆盖已存在的目标文件。旧命令标签配置与自动测试用例生成参数已退出当前接口。
